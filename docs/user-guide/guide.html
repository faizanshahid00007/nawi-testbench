1  What the prototype is

NAWI TestBench is a web application for laboratories that evaluate non-automatic weighing instruments (NAWIs) under OIML Recommendation R 76. The engineer records what the indicator shows; the software picks the permissible-error band for every load, applies the changeover-point correction and the zero-error correction, judges every test against its R 76 criterion, and produces the standardised report and, when everything passes, a certificate of conformity.

Everything the software knows about R 76 is stored as data in a versioned rule-set file. Every report remembers which rule set it was judged under, so a revised Recommendation becomes a new file, not new software.

2  Starting the software

The prototype runs on any computer with Node.js 20 or later. PDF export additionally needs Google Chrome, Chromium or Microsoft Edge installed; without one, HTML and Word exports still work.

cd ~/dev/nawi
npm install        # first time only
npm run seed       # first time only: two worked examples and the demo accounts
npm start          # then open http://localhost:4178

Leave the terminal window open while you use the software; closing it stops the server. To run it permanently, see docs/deployment.md.

If the page does not open, the server is not running. Run npm start again. If it reports that the port is in use, another copy is already running; stop that one first or start this one with PORT=5000 npm start.

5  Dashboard

  • Console readouts: tests on record, in progress, awaiting approval, certificates issued. Click a readout to open the Tests list filtered to that status.
  • New test and Add an instrument buttons (engineer and above).
  • Recent tests: the eight most recent reports. Click a row to open it.
  • Outcomes: how many tests currently pass, fail or are incomplete, and how many are certified. Below it, tests opened per month, per accuracy class, and totals of observations and attachments.

6  Instruments

An instrument is registered once and reused in every test made on it. Open Instruments in the rail and press Add an instrument.

6.2 What is checked as you type

The grey strip below the metrological fields shows n = Max / e and whether it lies in the range Table 3 permits for the class, the lowest Min allowed, whether the changeover method is required (d > 0.2 e), and any findings. An instrument can be saved with findings, but findings block the certificate, so fix them if they are data-entry mistakes.

6.3 Viewing and editing

Click any row in the instrument list to open its detail panel with all particulars and its test history. Edit particulars is available until the instrument appears in a closed or approved report; after that it is frozen so old reports stay truthful. New test on this instrument opens the New test form with the instrument pre-selected.

8  The report workspace

From top to bottom:

  1. Header: reference, dates, instrument, status badges, and the buttons All tests, Report (HTML in a new tab), Word, PDF and, once issued, Certificate.
  2. Error envelope: every load-based point plotted against the MPE staircase for the class. Black dots are within the limit, red dots outside; hover a dot for its values.
  3. Outcome panel: the LCD reads PASS, FAIL or ---- (incomplete), with DRAFT, CLOSED, APPROVED and CERT annunciators. Below it, what the purpose still requires and whether the report is eligible for a certificate.
  4. Workflow box: the action available at this stage (close, approve, return, reopen). See section 14.
  5. Instrument and Evaluation particulars.
  6. Laboratory environment readings with an add form (section 12).
  7. Test groups: Metrological performance, Influence factors, Time and stability, Construction and markings. Each test is a collapsible block with its clause, its verdict badge and its observation count. A coloured left edge repeats the verdict.
  8. Photographs and documents, Remarks, Audit trail.
  9. Navigator (right column, stays in view while scrolling): progress bar and a link to every test with a verdict dot. Click a test to jump to it and open it.

Everything is recalculated every time an observation is saved or removed. There is no “calculate” button.

9  Recording observations and the live readout

Open a test block and use the Record an observation form at its bottom. Fields common to the load-based tests:

Point / Position / RunA label for the report: “10 kg”, “Segment 2”, “Run 3”. Eccentricity offers the four segments; repeatability suggests the next run number.
DirectionIncreasing or decreasing load (A.4.4.1 asks for both).
LoadThe test load applied, in the instrument's unit.
TareTare test only: the tare value in use. The net load is judged.
IndicationWhat the display shows.
Added until display stepped, ΔLChangeover-point method: the small weights added until the display moved up one interval. Leave blank to use the raw reading. Required in spirit when d > 0.2 e.
Zero error E₀ at this pointOverrides the session E₀ for this point.
RemarkFree text printed under the row in the report.

9.1 What happens when you press Record

  • Errors stop the save and are shown under the form: load above Max (+ T), negative load, tare above T, missing second indication, missing time, a creep reading at a different load, a wrong tilt position.
  • Warnings let the save go through but are stored with the observation, shown as ⚠ next to the point, listed under the table and printed in the report: indication not a multiple of d, ΔL larger than one e, E₀ larger than one e, load below Min, a temperature or voltage outside the instrument's limits, a duplicate label.
  • The table, the envelope, the outcome panel and the navigator update at once.

9.2 The arithmetic behind each row

P  = I + ½e − ΔL      indication before rounding (blank ΔL → P = I)
E  = P − L            error of indication
Ec = E − E0           corrected error, compared with the MPE for L
MPE from Table 6:  ±0.5 e, ±1 e or ±1.5 e depending on L / e and the class; × 2 in service

11  Checklists

The two construction tests are inspections rather than measurements. For every item choose Yes, No or N/A and add a remark if useful. Rules:

  • A compulsory item (manufacturer's mark, class oval, Max, Min, e, legibility) must be Yes. No or N/A fails the test.
  • An if applicable item (serial number, software identification, T = +, special temperature limits and so on) may be N/A when the feature is absent. No fails the test.
  • The test stays INCOMPLETE until every compulsory item is answered.

12  Laboratory environment

Record temperature (°C), relative humidity (%), barometric pressure (hPa), supply voltage (V) and frequency (Hz) with a stage label such as “Start of test”, “During test”, “End of test” or “Temperature chamber”. Each reading is time-stamped. A reading outside the instrument's temperature limits or supply limits is saved with a warning. All readings are printed in section 2 of the report.

13  Photographs, documents and remarks

  • Drop images (JPEG, PNG, WebP), PDFs, text, CSV, Word or Excel files onto the drop zone, or click choose files. Up to 8 MB each. You are asked for a caption. Photographs appear in the PDF and HTML report; other documents are listed with type and size.
  • Remarks are free text for the report: instrument condition on arrival, deviations from procedure, test weights used.
  • The audit trail lists every action on the report with who did it and when.

14  Closing, approval and certificates

draft --close--> closed (awaiting approval) --approve--> approved (+ certificate if eligible)
  ^                  |                                       |
  +----- reopen -----+---- return to engineer ---------------+---- withdraw and reopen (approver)
  1. Engineer closes. Press Close report in the workflow box. Observations are frozen. If the battery is incomplete you are asked to confirm; the report is then filed as incomplete and cannot be certified.
  2. Approver reviews. Sign in as an approver and open the report. The workflow box offers an optional note, Return to engineer (reopens it with the note) and Approve and sign.
  3. Approval signs the report. A SHA-256 signature is computed over the instrument, every observation and check, every verdict and the approval record, and printed on the report. If the evaluation passed, every test required for the purpose is decided and the instrument has no classification findings, a certificate number like NAWI-C/2026/0001 is issued and the Certificate button appears.
  4. Verification. Anyone can open /verify/<certificate number> to confirm that the certificate exists and is current. Withdrawing the approval marks it as withdrawn.

16  Finding tests again

  • Search matches the reference, certificate number, applicant, manufacturer, model, serial number and application reference.
  • Filters: status (in progress, awaiting approval, approved), outcome (pass, fail, incomplete), accuracy class, purpose, and opened-from and opened-to dates. Selects apply immediately; press Apply after typing a search, Clear to reset.
  • Each row shows a progress bar of required tests decided, status, outcome, certificate number and opening date. Click a row to open the report.
  • Per-instrument history is on the instrument's detail panel.

17  Users and passwords

Admins create accounts with a username, full name, role and a password of at least eight characters, change a role from the drop-down, disable or enable an account, and reset passwords. Passwords are stored as scrypt hashes; sessions are HttpOnly cookies that expire after 12 hours.

18  The standard page

Use the calculator at the top to find the permissible error for any class, Max, e, load and context, and see where the load sits on the envelope. Below it are the accuracy-class table, the MPE bands, and every test with its rule, clause and whether type approval or verification requires it. This is the quickest way to answer “why did that point fail?”.

19  Worked examples

NAWI/2026/0001, Avery India CS-30 (fails)

Class III counter scale, Max 30 kg, e = d = 5 g, initial verification. At 20 kg (4000 e, band above 2000 e) the MPE is 1.5 e = 7.5 g. The display reads 20 010 g with no changeover recorded, so Ec = +10 g and the point fails; the whole evaluation therefore fails while the other nine weighing points, eccentricity, discrimination, tare, zero and the markings checklist pass. Repeatability is incomplete because only three of ten runs are recorded. Use this report to try recording, the live readout, closing and returning.

NAWI/2026/0002, Essae-Teraoka DS-852 (certified)

Class III platform scale, Max 15 kg, e = d = 5 g. All 17 tests recorded and passing, closed, approved and signed, certificate NAWI-C/2026/0001 issued. Use it to see a complete report, the Word and PDF exports, the certificate and the verify page. As an approver you can withdraw and reopen it, then close and approve it again to watch a certificate being issued.

21  Glossary

NAWINon-automatic weighing instrument: one that needs an operator during weighing (shop scales, platform scales, weighbridges).
Max, MinMaximum and minimum capacity. Results below Min are not subject to the MPE.
eVerification scale interval: the interval used for classification and for expressing the MPE.
dActual scale interval: what the display steps in. d ≤ e.
nMax / e, the number of verification scale intervals. Table 3 limits it per class.
MPEMaximum permissible error: ±0.5 e, ±1 e or ±1.5 e depending on the load band; doubled in service.
Changeover pointThe load at which a digital display steps to the next value; used to recover the indication before rounding (P = I + ½e − ΔL).
E, E₀, EcError of indication; zero error determined before the measurement; corrected error Ec = E − E₀, the value compared with the MPE.
Type approval / VerificationType approval evaluates a design with the full battery; verification checks an individual instrument with the metrological tests.
Initial verification / In serviceThe two MPE contexts of 3.5.1 and 3.5.2.
Rule setThe JSON file holding every constant of an R 76 edition. Reports remember which one they were judged under.
